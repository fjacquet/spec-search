# SPEC CPU2026 Suite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add SPEC CPU2026 as a third benchmark suite (alongside `cpu2017` and `jbb2015`), surfacing its full data including energy-efficiency metrics.

**Architecture:** Purely additive registry change. CPU2026's CSV columns are a superset of CPU2017's, so each registry (pipeline `SUITES`, MCP `SUITE_CONFIGS`/`VALID_SUITES`, web `SUITES`) gains one config entry. The web suite selector and comparison view auto-populate from the registry — no component code changes. Energy values of `0` (SPEC's "not measured" sentinel) are normalized to `null` in the data layer so existing `?? "—"` rendering shows them as not-reported.

**Tech Stack:** Python 3.12 (csv/json stdlib for pipeline; Pandas for MCP), FastMCP 3.x, React 19 + Vite 6, Pytest, Vitest, Ruff, Biome, uv, npm.

## Global Constraints

- Always run Python via `uv run`, never system Python.
- Two Python environments: repo root (for `scripts/`, `tests/`) and `mcp_server/` (for the server + its tests). Run MCP commands from inside `mcp_server/`.
- Web app is JSX (not TypeScript); lint/format with Biome; Python with Ruff.
- The Makefile is the single entry point for dev commands.
- Generated JSON under `web/public/data/<suite>/` is gitignored; CI regenerates it from the committed CSV.
- Docs (CHANGELOG, ADR, architecture, data-refresh) must stay in sync with code changes.
- Use Mermaid diagrams, never ASCII-art tables.
- Default suite stays `cpu2017`; do **not** change `DEFAULT_SUITE`.
- Benchmark labels (all three suites use this exact wording): `CINT*` → "Integer Per-Core", `CFP*` → "FP Per-Core", `CINT*rate` → "Integer Multi-Core", `CFP*rate` → "FP Multi-Core".

## Notes for the implementer

- **Column name stripping is automatic.** The live CSV header has trailing tabs/spaces (`"Hardware Vendor\t"`, `"Processor "`, `"# Chips "`). The pipeline strips row keys (`{k.strip(): v}`) and the MCP loader strips column names (`df.columns.str.strip()`), so the config maps use clean names — do not include the trailing whitespace in `column_map`/`rename_map` keys.
- **`Peak Result = 0`** rows (base-only runs, e.g. some Apple silicon) are valid and kept; they sort to the bottom under the default `peakResult` desc sort. This is expected, not a bug.
- **Do not change `DEFAULT_SUITE`** — CPU2017 stays the landing suite.
- **No web component changes** — `ResultsTable.jsx`, `ComparisonView.jsx`, `FilterBar.jsx`, and `App.jsx` all read the suite registry; adding the config entry is sufficient.
